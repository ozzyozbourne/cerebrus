Running an SDK example, and the one import fix you will need

Copy the example directory into your home directory or under $TMPDIR (never under /tmp), source /home/user/cerebras-sdk/env.sh, and run bash commands_wse3.sh (or _wse2). Most examples print SUCCESS!.

Five benchmarks, 7pt-stencil-spmv and the four CG-family solvers (conjugate-gradient, preconditioned-conjugate-gradient, bicgstab, power-method), import "../../benchmark-libs/…" by a relative path. In place in the extras tree they fail with error: Unable to open ./src/../../benchmark-libs/stencil_3d_7pts/layout.csl Measured. The reason is the wrapper: cslc and cs_python run inside a Singularity container that sees only the current directory, $TMPDIR and the paths in CSL_IMPORT_PATH (sdk_debug_shell binds exactly these; it also mounts $TMPDIR over the container's /tmp, so the host's /tmp is hidden) SDK 2.10.1, sdk_debug_shell. The fix is to keep benchmark-libs/ as a sibling of the example directory (copy both) where the container can see it:

  • Both copies under $TMPDIR (env.sh sets it to /home/user/cerebras-sdk/tmp): nothing else to do. 7pt-stencil-spmv copied there with its sibling ran to SUCCESS! with CSL_IMPORT_PATH unset Measured, WSE-3, 5 × 5 PEs.
  • Anywhere else, such as your home directory: the same copy fails, because the sibling is outside the container. Export CSL_IMPORT_PATH so that the wrapper bind-mounts it:
cp -r …/benchmarks/conjugate-gradient …/benchmarks/benchmark-libs ~/sdk/
cd ~/sdk/conjugate-gradient
export CSL_IMPORT_PATH=$(realpath ../benchmark-libs)  # wrapper bind-mounts it
bash commands_wse3.sh   # SUCCESS!, |xf_ref - xf_wse| = 3.05e-05

CSL_IMPORT_PATH takes colon-separated realpaths and is read by the host wrapper. The compiler flag cslc --import-path DIR adds a search directory for <…> imports, which is what the library's own comment asks for, but on its own it did not fix this failure in our tests: the relative path still has to be visible inside the container Measured, WSE-3, 5 × 5 PEs, 2 iterations.

Notes on particular examples

  • WSE-2 only: topic-14-color-swap (its README: "CSL currently does not support color swap on WSE-3"), histogram-torus, spmv-hypersparse and 25-pt-stencil ship only commands_wse2.sh SDK 2.10.1.
  • WSE-3 only: topic-15-wse3-microthreads (explicit microthread IDs exist only on WSE-3) and fft-3d, which is built on csl-libs/kernels/fft and uses input queues 2 and 4 and microthreads 2 and 3 by default SDK 2.10.1, kernels/fft/fft3d.csl.
  • Timing idiom. Several benchmarks time themselves with the TSC plus a synchronisation step and a reference stamp, time_ref: 7pt-stencil-spmv and the four CG-family solvers (sync through benchmark-libs/allreduce), bandwidth-test and row-col-broadcast (their own sync/ module), and spmv-hypersparse (its own allreduce and f_sync). Others do not: 25-pt-stencil and single-tile-matvec read <time> with no sync or time_ref, and game-of-life does not use the TSC SDK 2.10.1, grep of src/. The run.py scripts that convert cycles to time use 850 MHz. Appendix C explains the method and its 1-cycle-per-hop correction ("Synchronise, then correct").
  • device_run.py. The four CG-family benchmarks ship a second host script that moves the iteration loop onto the device. conjugate-gradient/run.py explains why: with the loop on the host, "I/O pressure is high, not good for performance. device_run.py removes this IO pressure" SDK 2.10.1. Chapter 15 builds the same two loops in its own program ("Host loop or device loop").
  • Libraries you can reuse. benchmark-libs/allreduce (row reduce, column reduce, broadcast back) and benchmark-libs/stencil_3d_7pts (with separate wse2/ and wse3/ implementations) are ordinary CSL modules that take colors and queues as parameters. kernels/tally is a two-phase completion counter ("every PE must signal completion at least once") used by histogram-torus SDK 2.10.1, kernels/tally/layout.csl. Both kernel libraries contain code paths for both chips (@is_arch("wse3") branches in tally/pe.csl and fft/fft_internal/transpose.csl); only their one consumer's script restricts them to one chip.
