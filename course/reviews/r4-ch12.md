## Errors

**E1 (med) · #streaming and #composing: gemv-08 is not store-and-forward.**
The page says: "The SDK's gemv-06/07/08 tutorials do `@fadds(y, in, y)` into memory and send in a separate step. That is store-and-forward per PE", and "[gemv-08's] per-PE reduction step stores into memory before sending, which is store-and-forward."
What the SDK does: gemv-06 and gemv-07 are only 2 PEs wide (`@set_rectangle(2, 1)` / `(2, 2)`). They have a first PE (`@fmovs(out, y)`) and a last PE (`@fadds(y, y, in)`) and no middle PE, so they forward nothing. gemv-08's middle columns run `@fadds(out_dsd, y_dsd, in_dsd, …)` (`tutorials/gemv-08-routes-3/pe_program.csl`, lines 89–94). That is fabric in + memory → fabric out, the same streaming op as program 03.
Fix: say that gemv-08's reduction uses program 03's streaming pattern (first/middle/last), and that only its x path differs (a data task `recv_x` per wavelet, `@fmacs` per scalar). Drop the store-and-forward claim from both places.

**E2 (med) · "What happens inside" (program 03), step 6: what launch() waits for.**
The page says: "`launch` returns on the host only after every PE has unblocked. `memcpy_d2h` then reads…"
Chapter 7 and Chapter 10 say the opposite, and CROSS_CHAPTER_NOTES 21 records it as measured. `launch(..., nonblock=False)` returns without waiting for the device. The *next* command (here the D2H) cannot run on a PE until that PE calls `unblock_cmd_stream()`.
Fix: "The host's next command, `memcpy_d2h`, waits on each PE until that PE has unblocked." Link to 07-host-io.

**E3 (med) · #late-pe: the buffer capacity contradicts its own example.**
The page says: "the 7 hops between it and the stalled PE held all 128 wavelets … Each hop … holds roughly 16 wavelets … a chain of P PEs buffers ≈ 16·(P − 1)." But 16 × 7 = 112, which is less than 128.
Where the 16 comes from: the drain spacing between adjacent PEs' end stamps (ch11-depth D3). Those stamps come from different PEs' clocks. The page's own #hop-cost section shows such clocks are offset by one router hop (2 cycles on WSE-3), so the true spacing is ≈ 18. That fits 128 / 7 ≈ 18.3.
Fix: "≈ 18 wavelets per hop (16 on own-clock readings plus the 2-cycle clock offset)". Change the rule of thumb to ≈ 18·(P − 1), or give a 16–18 range.

**E4 (med) · end of #hop-cost: chain vs tree contradicts Chapter 14.**
The page says: "With c ≈ 9, the P term equals the M term once P ≈ M / 9: around 30 PEs at M = 256. Past that point a tree or 2-D decomposition starts to beat one long chain."
Chapter 14's aside (14-lab-gemm.html, "Both the library's broadcast…") models a tree as log₂P·(15 + M) + 2(P − 1) and finds the tree wins from P ≈ 27 at M = 32. With that same model, at M = 256 the crossover is P ≈ 280, not 30 (chain 9P + 256 = 2,776 vs tree 2,761 at P = 280). Each tree level resends the whole M, so P ≈ M/9 says when hops dominate, not when a tree wins.
Fix: keep the "hops dominate past P ≈ M/9" statement. Replace the tree claim with a forward link to Chapter 14's model and its crossovers.

**E5 (low-med) · #two-colors stepper, one-color mode.**
The final frame says: "Result: a wrong answer or a stalled run." On WSE-3, the program's default, `rx = {WEST, RAMP}` does not compile. Chapter 4 measured `expected at most 1 input direction(s) on 'wse3', got: 2` and states this in its own checkerboard section.
Fix: in the hint or the last frame, add "on WSE-3 cslc rejects this route outright; on WSE-2 it compiles and gives this wrong answer."

**E6 (low) · #measuring paragraph: wrong chapter for the bank-clash rule.**
The page says: "…the bank clash that halves … `@fmacs` when its two source arrays start at addresses equal mod 4 words (Chapter 11)." The empirical mod-4 rule is Chapter 6's ("Layout matters: operand collisions in SRAM"). Chapter 11 says only that "the exact rule is not documented: pad and measure". Cite Chapter 6.

**E7 (low) · #hop-cost and "Going 2-D": dead paths and review jargon.**
"A variant of program 03 (in `tmp/fix-ch11/rt`)" and "(a copy is in `tmp/fix-ch11/b2d`)" point to `/home/user/cerebras-sdk/tmp/fix-ch11`, which does not exist. #late-pe opens with "The depth review delayed…", which is internal process wording. **E8 (low) · #collectives code excerpt.**
`reduce_fadds(W - 1, &v, &r, M, cb_id)` uses `W` and `r`, and neither is defined anywhere on the page (the row length is `P`). The layout assigns `const params = c2d.get_params(...)`, but the PE side reads `c2d_params.x`. Use `P - 1`, declare `r`, and show that `params` is passed as `.c2d_params`.
