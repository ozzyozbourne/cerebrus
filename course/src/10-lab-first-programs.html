Lab 1: SAXPY and wavelet tasks

Two single-PE programs. The first uses the host-driven style: copy data in, call a function, copy results out. The second uses the dataflow style: the host streams values, and each arriving wavelet runs a task. Both were compiled and run on the SDK 2.10.1 simulator for WSE-3 and WSE-2; the code below is the exact validated source.

After this lab you can

  • Write, compile and validate a complete single-PE program.
  • Bind a data task to a streaming input on both WSE-2 and WSE-3.
  • Spot and fix the race between streaming input and result readback.

What happens inside, in order

Where do the 7,740 simulated cycles go? Almost all of it is host I/O: two 64-element copies in, one out, plus command handling. The @fmacs itself processes 64 elements in on the order of tens of cycles. Lab 3 shows how to separate the two by measuring at two problem sizes and subtracting.

Program 02 · A task per wavelet

Now the host does not write into an array. It streams: each of the N values becomes one 32-bit wavelet sent on a memcpy color. On the PE, that color is bound to input queue 2 and the queue is bound to a data task, so each arriving value runs on_value() once, with the value as its argument.

The bug, and the debugging method

The first version had no wait_done. All 100 tasks fired and max/min were right, but the sum was 30.818 instead of 26.138. Steps taken:

  1. Copied the program to a scratch directory, added an exported seen[N] array, and recorded each received value: all 100 matched the input exactly, so the transport was fine.
  2. Recorded the running sum after each task instead: every partial sum matched numpy.cumsum. So the device computed the right answer.
  3. Searched the host-side cumulative sums for 30.818176: it is exactly the sum after 95 values.

Conclusion: the host read stats before the last five tasks ran. A streaming H2D completes when wavelets are injected, not consumed. wait_done() keeps the command stream blocked until on_value() sees the last value. Validated afterwards at N = 100 and N = 500, on WSE-3 and WSE-2.
