Lab 1: SAXPY and wavelet tasks

Two single-PE programs. The first uses the host-driven style: copy data in, call a function, copy results out. The second uses the dataflow style: the host streams values, and each arriving wavelet runs a task. Both were compiled and run on the SDK 2.10.1 simulator for WSE-3 and WSE-2; the code below is the exact validated source.

After this lab you can

  • Write, compile and validate a complete single-PE program.
  • Bind a data task to a streaming input on both WSE-2 and WSE-3.
  • Spot and fix the race between streaming input and result readback.
Run it yourself source /home/user/cerebras-sdk/env.sh, then in course/programs/01-saxpy run bash commands.sh (or ARCH=wse2 bash commands.sh). course/programs/run_all.sh runs every program and prints PASS/FAIL with cycle counts.

Program 01 · SAXPY: y ← a·x + y

The layout places one PE, exports two arrays and one function. Because the function takes an argument, its exported type is fn(f32)void.

course/programs/01-saxpy/layout.csl
// 01-saxpy: y = a*x + y on a single PE.
// Teaches: layout block, memcpy params, exported symbols, host-callable RPC.
param N: i16;      // vector length (compile-time)

const memcpy = @import_module("<memcpy/get_params>", .{ .width = 1, .height = 1 });

layout {
  @set_rectangle(1, 1);                         // 1 column x 1 row of PEs
  @set_tile_code(0, 0, "pe_program.csl", .{ .memcpy_params = memcpy.get_params(0), .N = N });

  @export_name("x", [*]f32, true);              // host may write and read
  @export_name("y", [*]f32, true);
  @export_name("saxpy", fn(f32)void);           // RPC taking the scalar a
}
course/programs/01-saxpy/pe_program.csl
param memcpy_params;
param N: i16;

const sys_mod = @import_module("<memcpy/memcpy>", memcpy_params);

// Both vectors live in this PE's 48 KB SRAM. There is no other memory.
var x: [N]f32;
var y: [N]f32;
var x_ptr: [*]f32 = &x;
var y_ptr: [*]f32 = &y;

// A DSD is a hardware loop descriptor: base address + length (+ stride).
const x_dsd = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{N} -> x[i] });
const y_dsd = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{N} -> y[i] });

fn saxpy(a: f32) void {
  // One instruction walks all N elements: y[i] = y[i] + x[i] * a
  @fmacs(y_dsd, y_dsd, x_dsd, a);
  // Tell memcpy this RPC is finished so the host's next command can run.
  sys_mod.unblock_cmd_stream();
}

comptime {
  @export_symbol(x_ptr, "x");
  @export_symbol(y_ptr, "y");
  @export_symbol(saxpy);
}
course/programs/01-saxpy/run.py
#!/usr/bin/env cs_python
import argparse, json
import numpy as np
from cerebras.sdk.runtime.sdkruntimepybind import SdkRuntime, MemcpyDataType, MemcpyOrder  # pylint: disable=no-name-in-module

p = argparse.ArgumentParser(); p.add_argument('--name'); p.add_argument('--cmaddr')
args = p.parse_args()
N = int(json.load(open(f"{args.name}/out.json"))['params']['N'])

rng = np.random.default_rng(0)
x = rng.standard_normal(N).astype(np.float32)
y = rng.standard_normal(N).astype(np.float32)
a = np.float32(2.5)

rt = SdkRuntime(args.name, cmaddr=args.cmaddr)
xs, ys = rt.get_id('x'), rt.get_id('y')
rt.load(); rt.run()
kw = dict(streaming=False, order=MemcpyOrder.ROW_MAJOR, data_type=MemcpyDataType.MEMCPY_32BIT, nonblock=False)
rt.memcpy_h2d(xs, x, 0, 0, 1, 1, N, **kw)        # (x0, y0, width, height, elems per PE)
rt.memcpy_h2d(ys, y, 0, 0, 1, 1, N, **kw)
rt.launch('saxpy', a, nonblock=False)
out = np.zeros(N, dtype=np.float32)
rt.memcpy_d2h(out, ys, 0, 0, 1, 1, N, **kw)
rt.stop()

np.testing.assert_allclose(out, a * x + y, rtol=1e-6, atol=1e-6)
print("first 4:", out[:4], " expected:", (a * x + y)[:4])
print("SUCCESS!")

The last digit of element 2 differs (…295 vs …293): the device computes y + x·a with a fused multiply-add while numpy rounds the product first. The test tolerates 1e-6 relative error.

What happens inside, in order

Where do the 7,740 simulated cycles go? Almost all of it is host I/O: two 64-element copies in, one out, plus command handling. The @fmacs itself processes 64 elements in on the order of tens of cycles. Lab 3 shows how to separate the two by measuring at two problem sizes and subtracting.

Program 02 · A task per wavelet

Now the host does not write into an array. It streams: each of the N values becomes one 32-bit wavelet sent on a memcpy color. On the PE, that color is bound to input queue 2 and the queue is bound to a data task, so each arriving value runs on_value() once, with the value as its argument.

course/programs/02-wavelet-tasks/layout.csl
// 02-wavelet-tasks: the host streams N numbers into one PE. Every arriving
// 32-bit wavelet triggers a *data task* that updates running statistics.
// Teaches: streaming memcpy, input queues, data tasks (wavelet-triggered tasks).
param N: i16;
param MEMCPYH2D_DATA_1_ID: i16;    // which color memcpy uses for our stream

const memcpy = @import_module("<memcpy/get_params>", .{
  .width = 1, .height = 1, .MEMCPYH2D_1 = MEMCPYH2D_DATA_1_ID });

layout {
  @set_rectangle(1, 1);
  @set_tile_code(0, 0, "pe_program.csl", .{ .memcpy_params = memcpy.get_params(0), .N = N });
  @export_name("stats", [*]f32, false);      // false = pointer is immutable (const)
  @export_name("count", [*]u32, false);
  @export_name("wait_done", fn()void);   // barrier RPC
}
course/programs/02-wavelet-tasks/pe_program.csl
param memcpy_params;
param N: i16;

const sys_mod = @import_module("<memcpy/memcpy>", memcpy_params);

// stats = [sum, sum of squares, max, min]
var stats = [4]f32 { 0.0, 0.0, -1.0e30, 1.0e30 };
var count = [1]u32 { 0 };
const stats_ptr: [*]f32 = &stats;
const count_ptr: [*]u32 = &count;

// The color memcpy streams on is chosen by the host side (a param).
const h2d_color: color = @get_color(@bitcast(u16, sys_mod.MEMCPYH2D_1));
// On WSE-3 a wavelet lands in an *input queue*; the data task is bound to the queue.
// (Queues 0 and 1 are reserved by memcpy on WSE-3, so we use 2.)
const h2d_iq: input_queue = @get_input_queue(2);
const recv_task_id: data_task_id =
  if (@is_arch("wse2")) @get_data_task_id(h2d_color)   // WSE-2: task ID == color
  else @get_data_task_id(h2d_iq);                      // WSE-3: task ID == input queue

// Runs once per wavelet; the 32-bit payload arrives as the argument.
task on_value(v: f32) void {
  stats[0] += v;
  stats[1] += v * v;
  if (v > stats[2]) stats[2] = v;
  if (v < stats[3]) stats[3] = v;
  count[0] += 1;
  // Last value processed: if the host is waiting in wait_done(), release it.
  if (count[0] == @as(u32, N) and host_waiting) sys_mod.unblock_cmd_stream();
}

// RPC the host calls after streaming. A streaming memcpy_h2d "completes" as
// soon as all wavelets are injected -- NOT when the data tasks have consumed
// them. Without this barrier the host reads half-finished statistics.
var host_waiting: bool = false;
fn wait_done() void {
  if (count[0] == @as(u32, N)) {
    sys_mod.unblock_cmd_stream();     // all done already
  } else {
    host_waiting = true;              // leave the command stream blocked;
  }                                   // on_value() unblocks it later
}

comptime {
  @bind_data_task(on_value, recv_task_id);
  @initialize_queue(h2d_iq, .{ .color = h2d_color });
  @export_symbol(stats_ptr, "stats");
  @export_symbol(count_ptr, "count");
  @export_symbol(wait_done);
}
course/programs/02-wavelet-tasks/run.py
#!/usr/bin/env cs_python
import argparse, json
import numpy as np
from cerebras.sdk.runtime.sdkruntimepybind import SdkRuntime, MemcpyDataType, MemcpyOrder  # pylint: disable=no-name-in-module

p = argparse.ArgumentParser(); p.add_argument('--name'); p.add_argument('--cmaddr')
args = p.parse_args()
params = json.load(open(f"{args.name}/out.json"))['params']
N, H2D = int(params['N']), int(params['MEMCPYH2D_DATA_1_ID'])

data = np.random.default_rng(1).uniform(-10, 10, N).astype(np.float32)

rt = SdkRuntime(args.name, cmaddr=args.cmaddr)
s_sym, c_sym = rt.get_id('stats'), rt.get_id('count')
rt.load(); rt.run()
# streaming=True: pass the *color id* instead of a symbol; each element becomes a wavelet.
rt.memcpy_h2d(H2D, data, 0, 0, 1, 1, N, streaming=True,
              order=MemcpyOrder.ROW_MAJOR, data_type=MemcpyDataType.MEMCPY_32BIT, nonblock=False)
rt.launch('wait_done', nonblock=False)   # barrier: wait until every task has run
kw = dict(streaming=False, order=MemcpyOrder.ROW_MAJOR, data_type=MemcpyDataType.MEMCPY_32BIT, nonblock=False)
stats = np.zeros(4, dtype=np.float32); count = np.zeros(1, dtype=np.uint32)
rt.memcpy_d2h(stats, s_sym, 0, 0, 1, 1, 4, **kw)
rt.memcpy_d2h(count, c_sym, 0, 0, 1, 1, 1, **kw)
rt.stop()

expected = np.array([data.sum(dtype=np.float32), (data * data).sum(dtype=np.float32), data.max(), data.min()], dtype=np.float32)
print("tasks fired:", count[0], " stats:", stats, " expected:", expected)
assert count[0] == N
np.testing.assert_allclose(stats, expected, rtol=1e-4)
print("SUCCESS!")

The bug, and the debugging method

The first version had no wait_done. All 100 tasks fired and max/min were right, but the sum was 30.818 instead of 26.138. Steps taken:

  1. Copied the program to a scratch directory, added an exported seen[N] array, and recorded each received value: all 100 matched the input exactly, so the transport was fine.
  2. Recorded the running sum after each task instead: every partial sum matched numpy.cumsum. So the device computed the right answer.
  3. Searched the host-side cumulative sums for 30.818176: it is exactly the sum after 95 values.

Conclusion: the host read stats before the last five tasks ran. A streaming H2D completes when wavelets are injected, not consumed. wait_done() keeps the command stream blocked until on_value() sees the last value. Validated afterwards at N = 100 and N = 500, on WSE-3 and WSE-2.
