Appendix A · Reference

Glossary and number formats

Every Cerebras, CSL and SDK, Tenstorrent and GPU term the course uses, defined in a sentence or two and linked to the section that explains it. Then the number formats the three machines' peak figures are quoted in, with their bit layouts, two explorers and a table of which machine runs which format.

Use this appendix to

  • Look up a term you met in a chapter, a paper or an SDK example, and jump to the section that teaches it.
  • Read any 4-, 8-, 16- or 32-bit float bit by bit, and see how much precision each format keeps.
  • See why block-scaled formats (BlockFP8, NVFP4, MXFP4) can store 4 to 8 bits per value, and what an outlier does to them.
  • Check which machine supports a format before you compare two peak figures.

Provenance tags work as in the chapters: Vendor Independent SDK 2.10.1 Measured Derived Unverified. Glossary definitions repeat what the linked chapter says, and that chapter's tags apply. The CUDA-to-CSL map, the per-PE budget and the measured cost constants are in Appendix B.

A
ActivateCSL & SDK#
Mark a task ready to run by setting its activated bit, with @activate(id) in code or .activate = id on an async op. The bit is a single bit, so two activations that land before the task runs give one run.See Ch. 5, What the hardware stores
Arithmetic intensityGeneral#
FLOPs a kernel performs per byte it moves to or from one memory level. Below the ridge point the kernel is bandwidth-bound.See Ch. 1, Two numbers
Async operationCSL & SDK#
A DSD instruction marked .async = true. It runs on a microthread while the task that issued it ends, and its completion can activate or unblock a task.See Ch. 6, Async operations
B
Back-pressureCerebras#
When a router's buffer for a color is full, the wavelet waits where it is and the stall spreads upstream until the sender stops. The fabric never drops data; a slow receiver slows its sender.See Ch. 4, Nothing is dropped · Ch. 12, When a PE is late
Bank (SRAM bank)Cerebras#
The 48 KB SRAM is 8 single-ported banks. The SDK's rule is that bits [3:1] of the byte address pick the bank (a 16-byte stripe); papers describe 32-bit interleaving instead, and the physical bank width is not published.See Ch. 3, Which bank does an address land in?
Bank clash (operand collision)Cerebras#
An empirical rule from this course's runs: @fmacs runs at half speed when its two source streams start at word addresses equal mod 4. Padding one array by a word fixes it; the exact rule is undocumented, so pad and measure.See Ch. 6, Layout matters · App. B, constants
Blackhole, Wormhole, GrayskullTenstorrent#
Tenstorrent chip generations. Blackhole p150 (TSMC 6 nm): 120 enabled Tensix cores, 1,536 KiB L1 each, 32 GB GDDR6. Wormhole n300: two dies of 64 cores. Grayskull is legacy.See Ch. 16, The product line
Block / unblockCSL & SDK#
@block(id) stops a task from being picked even if it is activated; @unblock(id) or .unblock = id on an async op releases it. A blocked data task leaves its wavelets waiting in the input queue.See Ch. 5, Blocking
BRISC / NCRISC / TRISCTenstorrent#
The five small RISC-V cores in a Tensix: BRISC usually runs the reader, NCRISC the writer, and TRISC0/1/2 run unpack, math and pack from one compute source compiled three times.See Ch. 16, Inside a Tensix core · Ch. 16, Programming
BuiltinCSL & SDK#
A CSL function whose name starts with @. The DSD builtins (@fmovs, @fadds, @fmacs, @fmach, ...) are the PE's vector instruction set; the naming code is s = f32, h = f16, hs = f16 in, f32 out.See Ch. 6, Builtins
C
Channel (memcpy I/O channel)CSL & SDK#
One host I/O link with its own demux serving a band of rows; --channels accepts up to 16. The SDK quotes about 7 Gb/s per channel on hardware.See Ch. 7, The narrow door · Ch. 7, The memcpy frame
CheckerboardCerebras#
Alternating two colors by column (or row) parity so that every PE in a chain has one-in, one-out routes. It is needed because a route sends every arriving wavelet to every tx port, so one color cannot both receive and forward at a middle PE.See Ch. 4, Why programs alternate colors · Ch. 12, Why two colors?
Circular buffer (CB)Tenstorrent#
A FIFO of fixed-size pages in L1 with producer and consumer counters, the hand-off between reader, compute and writer kernels. Up to 32 per core on Wormhole, 64 on Blackhole; two slots give double buffering.See Ch. 16, Programming: reader, compute, writer
CoalescingGPU#
Merging a warp's 32 loads into as few 32-byte sectors as possible. Contiguous access uses every fetched byte; a strided or gathered access wastes most of each sector.See Ch. 17, Coalescing
<collectives_2d>CSL & SDK#
The SDK library of MPI-style broadcast, scatter, gather and reduce along rows and columns, with two colors per axis. It costs about 700 extra cycles against hand-written static routes.See Ch. 12, The library version
ColorCerebras#
A virtual channel: a tag on each wavelet that selects a pre-set route at every router and, at the receiver, which queue or task gets the data. There are 24 routable colors on both chips; they share each link's one word per cycle.See Ch. 4, A mesh of five-port routers · Ch. 4, Colors are the scarcest resource
Color swapCerebras#
A WSE-2 router feature that flips the lowest color bit as a wavelet passes, giving a checkerboard with one identical route on every PE. CSL does not support it on WSE-3.See Ch. 4, Why programs alternate colors
Command streamCSL & SDK#
memcpy's per-PE queue of host commands on color 22. Commands run one at a time; a PE decodes the next one only after the current one unblocks it.See Ch. 7, The command stream
comptimeCSL & SDK#
Code the compiler evaluates: a comptime { } block holds bindings (@bind_local_task, @initialize_queue) and exports.See Ch. 10, Hardware parts
Compute engine (CE)Cerebras#
The processor half of a PE: the task picker, 16 GPRs, 48 DSRs, the SIMD datapath and 8 microthreads (WSE-3 figures), next to the 48 KB SRAM. It is woken by wavelets arriving down the RAMP.See Ch. 3, The anatomy
Control taskCSL & SDK#
A task woken by a control wavelet whose payload names its ID; it gets the 16-bit lower half as data. The compiler accepts IDs 0–63; memcpy uses 33–37 and 40.See Ch. 5, Control tasks and sentinels
Control waveletCerebras#
A wavelet with its control flag set. Its bits carry router commands (NOP, SWITCH_ADV, SWITCH_RST, TEARDOWN) and optionally a control-task ID and 16 bits of data for the receiving CE.See Ch. 4, Control wavelets
Copy mode / streaming modeCSL & SDK#
Two memcpy flavours. Copy mode writes or reads an exported array and completes only when the data is in memory. Streaming mode delivers wavelets on a color to your data task, and completes once memcpy has handed them on.See Ch. 7, Copy mode vs streaming mode
CS-2, CS-3, CS-4Cerebras#
The systems built around one wafer: CS-2 holds a WSE-2, CS-3 a WSE-3 (~23 kW, 15U). CS-4 is a rack of three WSE-3T wafers.See Ch. 8, The system around the wafer
cs_pythonCSL & SDK#
The SDK's wrapper that runs your host script (run.py) with the SDK's Python runtime inside the Singularity image. It fails if run under /tmp.See Ch. 10, From source to simulation
cs_readelfCSL & SDK#
The SDK tool that inspects compiled PE programs: -m prints memory used per PE, --sym shows banks, --routing shows routes.See Ch. 10, Where did my 48 KB go?
csdbCSL & SDK#
The SDK's debugger (memory, register, trace, wavelet subcommands). This course verified only its help screens.See Ch. 10, When it hangs
CSLCSL & SDK#
The Cerebras Software Language: a Zig-like language with builtins for colors, queues, tasks and DSDs, compiled by cslc.See Ch. 10, The language in one screen
cslc / cslc-driverCSL & SDK#
The CSL compiler. cslc is a Python wrapper that checks the memcpy frame and forwards other flags to cslc-driver; --arch defaults to wse2.See Ch. 10, Flags · Ch. 10, What cslc actually builds
CUDA graphGPU#
A recorded sequence of kernel launches replayed as one unit to avoid per-kernel launch overhead, used by serving stacks for decode.See Ch. 17, One token, step by step
D
Data taskCSL & SDK#
A task that runs once per arriving wavelet and receives its 32-bit payload. On WSE-2 its ID is the color; on WSE-3 it is bound to an input queue (0–7), which is bound to a color.See Ch. 5, What activates a task
Dataflow sparsityCerebras#
Because work is triggered by arriving data, zeros that are never sent never trigger work. Cerebras's sparse FLOPS headlines count the skipped multiplies as if they were done.See Ch. 3, Sparsity
<debug> / <simprint>CSL & SDK#
Libraries for seeing inside a run: <simprint> prints to sim.log, <debug> fills trace buffers the host reads after stop().See Ch. 10, When it hangs
Decode / prefillGeneral#
Decode generates one new token per step and reads every weight once, about 1 FLOP per byte at batch 1. Prefill processes the whole prompt at once and is compute-bound.See Ch. 1, Why LLM decode lives on the slanted part
Dense / sparse FLOPSGeneral#
Dense peaks assume every multiply is done. Sparse headlines count skipped zeros as done: 2× for NVIDIA's 2:4 sparsity, and Cerebras's 125 PF WSE-3 figure is sparse FP16.See Ch. 17, number formats · Ch. 2
DivergenceGPU#
When threads of one warp take different branches, the warp runs each path in turn with the other lanes masked off.See Ch. 17, SIMT
DSD (data structure descriptor)CSL & SDK#
A value that describes a whole vector operand: base address, length and stride for memory, or a queue and extent for the fabric. One DSD instruction walks it in hardware, with no per-element fetch or branch.See Ch. 6, One instruction, a whole loop
DSR (data structure register)Cerebras#
A register that holds one DSD while an instruction uses it. A WSE-3 core has 48 (no WSE-2 count is published); with .save_address = true a DSR keeps its end address so the next op continues from there.See Ch. 6, Where the descriptor lives · Ch. 3, SIMD lanes
E
@export_name / @export_symbolCSL & SDK#
How the host finds device names: @export_name in layout.csl declares the name and type, @export_symbol in pe_program.csl binds it, and run.py looks it up with get_id.See Ch. 10, Three files
F
FabricCerebras#
The on-wafer 2-D mesh that links each PE's router to its four neighbours. Each link carries one 32-bit wavelet per cycle per direction; routes are fixed at load time.See Ch. 4, A mesh of five-port routers
Fabric DSDCSL & SDK#
A DSD that names a hardware queue instead of memory: fabin_dsd receives the next extent wavelets, fabout_dsd sends them. WSE-3 allows at most one fabric input per operation.See Ch. 6, Fabric DSDs
--fabric-dims / --fabric-offsetsCSL & SDK#
The size of the whole simulated fabric and where your rectangle starts. With memcpy the fabric must be at least 7 columns wider and 2 rows taller than your rectangle, at offsets 4,1.See Ch. 10, The fabric-size rule
Fidelity (LoFi, HiFi2–4)Tenstorrent#
How many passes the Tensix 5-bit × 7-bit multipliers make over the mantissas: LoFi uses one, HiFi2/3/4 two to four, at 16 to 64 cycles per tile.See Ch. 16, Inside a Tensix core
FIFOCSL & SDK#
@allocate_fifo(buffer) turns an SRAM array into a ring that one async op pushes into and another pops from. It costs two microthreads plus the buffer, and stretches the tiny hardware queues.See Ch. 6, FIFOs extend the tiny hardware queues
Filter (range, counter)Cerebras#
Router logic that decides which wavelets reach the CE. A range filter keeps upper-16-bit indices in a range; a counter filter keeps every k-th wavelet, which memcpy uses to deal a stream across a row. Each PE has 6.See Ch. 4, Filters · Ch. 7, How a copy reaches its PE
FlitTenstorrent#
The unit that crosses one NoC link per cycle: 32 B on Wormhole, 64 B on Blackhole. A packet is a header flit plus up to 256 data flits.See Ch. 16, The chip: a grid on two tori
--fp16-formatCSL & SDK#
The cslc-driver flag that chooses what CSL's f16 type means: IEEE half (f16), bfloat16 (bf16) or Cerebras's cb16.See Ch. 10, Flags · this appendix, formats
FPU / SFPUTenstorrent#
The Tensix matrix engine (matmul, reductions, element-wise ops on SrcA/SrcB) and the 32-lane FP32 vector unit for transcendental functions, which works on Dst.See Ch. 16, Inside a Tensix core
G
Galaxy / QuietBoxTenstorrent#
Multi-chip Tenstorrent systems: a Galaxy is 32 chips in a 2-D Ethernet mesh or torus; a QuietBox holds four cards.See Ch. 16, The product line · Ch. 16, 70B on 32 chips
GEMV / GEMM / SAXPYGeneral#
BLAS kernels: matrix-vector (y = A·x, decode's core op), matrix-matrix, and y = a·x + y (Lab 1's first program).See Ch. 11, Program 01 · Ch. 12, a distributed GEMV
GPRCerebras#
One of the 16 general-purpose registers of a WSE-3 CE, used for scalars and addresses.See Ch. 3, SIMD lanes
Grid tile / harvestingTenstorrent#
A location on the Tenstorrent chip grid (Tensix, DRAM, Ethernet, PCIe tiles). Harvesting fuses off defective rows or columns so software sees a smaller grid.See Ch. 16, The chip
H
HaloGeneral#
Two meanings in this course. In a stencil, the edge cells a PE copies from its neighbours (ghost cells, the halo exchange). In memcpy's layout, the outermost idle ring of PEs around the frame.See Ch. 13, The problem · Ch. 7, The memcpy frame
HBMGPU#
High Bandwidth Memory: DRAM stacks beside the GPU die in its package. An H100 has 80 GB at 3.35 TB/s, with hundreds of cycles of latency.See Ch. 17, The memory hierarchy · Ch. 1
HGX / NVL72GPU#
An 8-GPU board and a 72-GPU rack, each one NVLink domain.See Ch. 17, Scaling out
HopCerebras#
One router-to-router step of a wavelet. In the SDK simulator a pure router hop costs 2.0 cycles on WSE-3 and 1.0 on WSE-2; a hop through a PE's program (receive, add, send) costs about 9.2 and 6.0.See Ch. 4, Latency is paid once · Ch. 12, The hop cost
I
Input queue / output queueCerebras#
Small hardware FIFOs between the router and the CE. WSE-2 has 8 input and 6 output queues, WSE-3 8 and 8; on WSE-3 each queue is bound to one color with @initialize_queue. memcpy owns queue 0 (and 1 on WSE-3).See Ch. 5, The path from wire to code · Ch. 7, What memcpy reserves
Instruction traceCSL & SDK#
A per-cycle log of every instruction, enabled with SINGULARITYENV_SIMFABRIC_DEBUG=inst_trace. It shows which task each PE runs and where it stopped; use it on small runs.See Ch. 11, Look inside: the instruction trace
Interleaved / shardedTenstorrent#
Two tensor layouts: interleaved spreads pages round-robin over all banks; sharded gives each core or bank one contiguous piece.See Ch. 16, Where tensors live
@is_archCSL & SDK#
A compile-time test for the target chip, used to write one source file for both WSE-2 and WSE-3.See Ch. 10, Writing for both chips
J
JoinCSL & SDK#
Running a task only after two independent events: one op blocks it and later unblocks it on completion, another event activates it. Because the picker needs activated = 1 and blocked = 0, the two bits act as an AND gate.See Ch. 5, Block + activate = join
K
Kernel (CUDA)GPU#
A GPU function launched over a grid of thread blocks with <<<grid, block>>>. A kernel boundary acts as a global barrier: the next kernel sees everything the previous one wrote.See Ch. 17, SIMT · Ch. 17, SAXPY, twice
Kernel stall (error)CSL & SDK#
The host runtime's message “the received length (0 bytes) is not expected … could be a kernel stall”, printed when a copy never completes, usually because an RPC never unblocked the command stream.See Ch. 10, Error decoder
KV cacheGeneral#
The keys and values of every earlier token, kept per sequence and re-read by attention on every decode step. Llama-3-70B needs about 320 KiB per token at 16 bits.See Ch. 8, Inference · Ch. 1
L
L1 / L2 cacheGPU#
Hardware caches: L1 is carved from each SM's 256 KB of SRAM, L2 is a 50 MB chip-wide cache on H100. A PE has neither.See Ch. 17, The memory hierarchy · Ch. 3, Why no caches?
Latency hiding / ILPGPU#
A GPU covers memory latency by keeping many warps resident (occupancy) and many loads in flight per warp (instruction-level parallelism); Little's law says bytes in flight = bandwidth × latency.See Ch. 17, Latency hiding by occupancy
launch / RPCCSL & SDK#
rt.launch('f', args) runs exported device function f on every PE of the rectangle. It returns without waiting for the device; the next command waits until each PE calls unblock_cmd_stream().See Ch. 7, The host side in eight lines
Layer-pipelined modeCerebras#
The original Cerebras execution mode: every layer of a small model gets its own rectangle (region) of the wafer, and activations flow from region to region. Pinned-weight inference reuses the idea.See Ch. 8, Before weight streaming
layout.csl / pe_program.csl / run.pyCSL & SDK#
The three files of a program: the layout runs at compile time and places code and routes, the PE program runs on each PE, and run.py runs on the host.See Ch. 10, Three files, three places
<layout>CSL & SDK#
The library that gives a PE its own coordinates at run time (get_x_coord(), get_y_coord()), instead of passing them as params.See Ch. 10, Hardware parts
Local taskCSL & SDK#
A task started by code (@activate) or by a finishing async op. On WSE-3 local task IDs are 8–30; the course keeps user IDs in 8–20 to stay clear of memcpy.See Ch. 5, What activates a task · Ch. 5, Budget check
M
memcpyCSL & SDK#
The SDK's host-I/O runtime. It adds frame PEs around your rectangle and code on every PE, and reserves colors 20–23, some task IDs and queue 0 (and 1 on WSE-3).See Ch. 7, The memcpy frame · Ch. 7, What memcpy reserves
memcpy frameCSL & SDK#
The extra PE programs --memcpy places around your rectangle: halo + demux adaptor + demux + command fan on the west, mux + adaptor + halo on the east, one halo row above and below.See Ch. 7, The memcpy frame
memcpy_h2d / memcpy_d2hCSL & SDK#
SdkRuntime calls that copy host arrays to (H2D) or from (D2H) a rectangle of PEs: region x, y, width, height, elements per PE, plus order, data type, streaming and nonblock flags.See Ch. 7, The host side
MemoryXCerebras#
The off-wafer DRAM-plus-flash service that stores weights and optimizer state for weight-streaming training, streams weights to the wafers and applies the weight update.See Ch. 8, MemoryX
MicrothreadCerebras#
A hardware slot that holds one in-flight async vector operation. A PE has 8. On WSE-2 a fabric op runs on the microthread equal to its queue ID; on WSE-3 you can choose with .ut_id (default: the queue ID). Two concurrent ops must never share one.See Ch. 3, Microthreads · Ch. 5, A real hang
MulticastCerebras#
A route with several tx ports, such as rx NORTH → tx {RAMP, SOUTH}: one wavelet is copied to the local CE and forwarded, so one send reaches a whole column.See Ch. 4, Routes are set at load time · Ch. 12, Program 05
N
NIUTenstorrent#
The network interface unit in each grid tile, which turns reads and writes into NoC packets.See Ch. 16, The chip
NoC (Tenstorrent)Tenstorrent#
Each Tenstorrent chip has two 2-D torus networks: NoC 0 flows right then down, NoC 1 up then left. Packets carry their destination address; a router-to-router hop takes 9 cycles.See Ch. 16, The chip: a grid on two tori
NVLink / NVSwitchGPU#
NVIDIA's GPU-to-GPU link and the switch chip that joins many GPUs at NVLink speed (900 GB/s per H100, 1.8 TB/s per B200, bidirectional).See Ch. 17, Scaling out
O
OccupancyGPU#
How many warps fit on an SM at once, limited by registers per thread, shared memory per block and the 64-warp, 32-block caps. More resident warps hide more latency.See Ch. 17, Occupancy
P
paramCSL & SDK#
A compile-time constant passed from the layout or from --params (unsigned integers only). PEs with different params become different PE programs.See Ch. 10, Hardware parts
PE (processing element)Cerebras#
One of about 900,000 small computers on a WSE-3: a compute engine with 48 KB of private SRAM and a five-port router. Cerebras also says core or tile.See Ch. 3, The anatomy
Pinned-weight inferenceCerebras#
The Cerebras inference mode: every weight and the KV cache stay in wafer SRAM, layers are mapped to regions, and tokens flow through the regions and across wafers as a pipeline.See Ch. 8, Inference: pin the weights
Q
@queue_flushCSL & SDK#
On WSE-3, asks the hardware to run teardown task 29 once an output queue drains, so the queue can be rebound to a new color.See Ch. 5, Reusing a queue on WSE-3
R
RAMPCerebras#
The router's fifth port, which connects it to its own compute engine. Wavelets go down the ramp to be processed and up the ramp to be sent.See Ch. 4, A mesh of five-port routers
Reader / compute / writer kernelsTenstorrent#
The usual TT-Metalium split: a reader pulls tiles into circular buffers, a compute kernel consumes and fills CBs, a writer pushes results out.See Ch. 16, Programming
Register fileGPU#
65,536 32-bit registers (256 KB) per H100 SM, shared by all resident threads; registers per thread trade against occupancy.See Ch. 17, Inside an SM
ReticleGeneral#
The largest area a lithography tool exposes at once, about 26 × 33 mm, which caps the size of a normal die. Cerebras wires across the scribe lines between reticle fields so the fabric spans the whole wafer.See Ch. 2, From reticle to wafer
Ridge point / rooflineGeneral#
Peak FLOP/s divided by bandwidth of one memory level. The roofline plots attainable FLOP/s against arithmetic intensity; each memory level has its own ridge.See Ch. 1, Two numbers describe every accelerator
Route (rx / tx)Cerebras#
For each PE and color, the input port a wavelet is accepted from (rx) and the set of ports it is sent to (tx), set at load time with @set_color_config. A WSE-3 route accepts exactly one rx direction.See Ch. 4, Routes are set at load time · Ch. 4, Under the hood
RouterCerebras#
The switch in every PE with five bidirectional ports: NORTH, SOUTH, EAST, WEST and RAMP. It forwards wavelets by color according to routes fixed at load time.See Ch. 4, A mesh of five-port routers
Run to completionCSL & SDK#
A task runs until it returns and must never wait for something another task has to do; a blocking fabric op inside a task can deadlock the PE. Long work goes in async ops.See Ch. 5, Run to completion
Runtime args / CoreRangeTenstorrent#
There is no global thread ID in TT-Metalium; the host gives each core explicit runtime arguments, often per CoreRange.See Ch. 16, Programming · Ch. 16, CSL ↔ Metalium
S
SdkLayoutCSL & SDK#
The SDK's newer Python layout API: code regions, painted routes with symbolic colors, automatic routing between ports, and no memcpy frame.See Ch. 10, The other way to lay out
SdkRuntimeCSL & SDK#
The host-side Python class: SdkRuntime(dir, cmaddr), load(), run(), memcpy_h2d/d2h, launch, stop(). cmaddr=None runs the simulator.See Ch. 7, The host side in eight lines
Semaphore (L1)Tenstorrent#
A word in L1 updated by NoC atomics. Because NoC transfers are asynchronous and there are no data-triggered tasks, kernels use semaphores to signal that data has arrived.See Ch. 16, Moving tiles between cores
SentinelCSL & SDK#
A control wavelet sent after a data stream, whose payload names a control task that runs once the stream has ended.See Ch. 5, Control tasks and sentinels
@set_rectangle / @set_tile_codeCSL & SDK#
Layout builtins: the size of your PE rectangle, and which code file and params each PE gets.See Ch. 10, Three files
Shared memoryGPU#
A programmer-managed scratchpad inside each SM (up to 228 KB on H100) shared by one thread block: the GPU structure closest to a PE's SRAM.See Ch. 17, The memory hierarchy
SIMTGPU#
Single Instruction, Multiple Threads: you write scalar code for one thread, and the hardware issues 32 threads (a warp) as one SIMD instruction.See Ch. 17, SIMT: grids, blocks and warps
Simulator (SDK fabric simulator)CSL & SDK#
The cycle-level simulator every lab here runs on. It writes sim.log and sim_stats.json; whole-run cycle counts vary with host load, in-kernel TSC times do not. It does not model the host's Ethernet link.See Ch. 10, Simulator outputs
SM (streaming multiprocessor)GPU#
The GPU's core: four sub-partitions, each with a warp scheduler, 32 FP32 lanes and a Tensor Core, sharing 256 KB of L1/shared memory. An H100 SXM has 132.See Ch. 17, Inside an SM
Software-managed cacheCerebras#
A tiny per-PE cache, 256 B on WSE-2 and 512 B on WSE-3, that hardware never fills automatically. The CSL library does not expose it, and nothing in this course uses it.See Ch. 3, Is memory fast enough?
SrcA / SrcB / DstTenstorrent#
The Tensix engine's register files: unpackers fill SrcA and SrcB, the FPU accumulates into Dst, packers drain Dst to L1 (converting format on the way).See Ch. 16, Inside a Tensix core
StencilGeneral#
An update where each cell's new value depends on a fixed pattern of neighbours, like Lab 3's 1-D heat rod.See Ch. 13, The problem
Store-and-forward vs streamingGeneral#
Store-and-forward waits for a whole message at each hop (cost about P × M); streaming forwards each element as it arrives (about M + c·P). Lab 2 measured 348 vs 101 cycles at P = 8, M = 32.See Ch. 12, Why it is fast
SwarmXCerebras#
The broadcast–reduce network between MemoryX and many CS systems: it copies each layer's weights to every wafer and sums the gradients on the way back.See Ch. 8, SwarmX
Switch (route positions)Cerebras#
A color can hold up to four route positions; a control wavelet with SWITCH_ADV moves the router to the next one after the wavelet itself has passed. One switching color can replace several static ones.See Ch. 4, Switches
T
TaskCSL & SDK#
An entry point the hardware can start: data, local or control. The task picker runs any task whose activated bit is 1 and blocked bit is 0; tasks never call each other, they activate each other.See Ch. 5, What activates a task · Ch. 5, Tasks are entry points
Task IDCSL & SDK#
The number a task is bound to. Activatable IDs are below 31; WSE-3 local IDs run 8–30; control IDs 0–63; 29 is the teardown task. Keep your local tasks to 8–20.See Ch. 5, Budget check · App. B, budget
Task pickerCerebras#
The hardware that chooses the next task from those activated and not blocked. A 32-bit priority vector marks IDs 0–31 high or low; the order among equal-priority tasks is not documented.See Ch. 5, When several tasks are ready
TeardownCerebras#
A router state entered by a TEARDOWN control wavelet (or, on WSE-3, a flushed output queue draining) that runs local task 29, whose handler can rewrite routes. memcpy registers handlers there, so never bind your own task to 29.See Ch. 4, Teardown · Ch. 5, Reusing a queue
TensixTenstorrent#
One Tenstorrent core: five RISC-V cores, a matrix FPU, a 32-lane SFPU, about 1.5 MiB of L1 SRAM and two NoC routers.See Ch. 16, Inside a Tensix core
Tensor CoreGPU#
The matrix multiply-accumulate unit in each SM sub-partition, where almost all AI FLOPs come from: 512 dense BF16 FMAs per clock each on Hopper.See Ch. 17, Where the 989 TF comes from
Thread block / gridGPU#
A kernel runs as a grid of thread blocks; each block runs on one SM and shares a slice of its shared memory. blockIdx and threadIdx tell a thread which work is its own.See Ch. 17, SIMT
Thread-block clusterGPU#
Hopper groups blocks on neighbouring SMs into clusters that can read each other's shared memory (distributed shared memory).See Ch. 17, Hopper
Tile (32 × 32)Tenstorrent#
Tenstorrent's data unit: a 32 × 32 block (2,048 B in BF16), stored as four 16 × 16 faces. Tensors are padded to whole tiles.See Ch. 16, Inside a Tensix core
Timestamp counter (TSC)CSL & SDK#

Number formats

A floating-point number is a sign bit, an exponent field and a mantissa (fraction) field. With an exponent field of e bits and bias b, a normal number is (−1)s × 1.mantissa × 2exponent−b, and an all-zero exponent gives subnormals near zero. More exponent bits buy range; more mantissa bits buy precision. A 16-bit budget can be split either way: IEEE half (fp16) keeps precision, bfloat16 keeps fp32's range. Block formats go further and share one exponent or scale among a block of values. Peak FLOP figures roughly double with each halving of bits (Chapter 17), so read the format before the number.

What CSL's f16 is: a check in the compiler

We compiled a one-PE program that stores @bitcast(u16, @as(f16, v)) for sixteen constants and read the words back Measured, cslc + simulator 2.10.1, WSE-3. With the default format, 1.0 is 0x3C00, 2.0 is 0x4000, 0.5 is 0x3800, 1.5 is 0x3E00 and 1 + 2−6 is 0x3C10: exactly IEEE half precision. Two more findings:

  • The same constants gave the same bit patterns with --fp16-format=bf16 and =cb16, so in this test the flag did not change how compile-time constants are encoded Measured. The test cannot tell whether the hardware then reads those words differently.
  • With bf16 or cb16 selected, any run-time f16 variable or array (var h: [16]f16;) failed to compile with error: variable of type '[16]f16' must be comptime-known, on both --arch=wse2 and wse3 Measured. So in SDK 2.10.1 a kernel cannot switch its f16 arrays to bfloat16 just with this flag. The SDK documentation for the flag was not available here; how cb16 is meant to be used stays open.

Block formats: sharing a scale

An 8-bit or 4-bit float on its own has too little range for real tensors. Block formats give a small group of values one shared exponent or scale, chosen from the block's largest magnitude, and keep only a few bits per value. Tenstorrent's bfloat8_b shares one 8-bit exponent among 16 values and rounds to nearest-even after aligning each value to it Vendor, tt-metal data_formats. NVFP4 stores each value as E2M1 and each block of 16 with an E4M3 scale, plus one FP32 scale per tensor Vendor. The cost is that one large value in a block squeezes the small ones next to it into fewer bits. Try the outlier switch.

Three rules for reading a peak

  • Find the format. B200's 9 PF is FP4; at BF16 it is about 2.25 PF (Ch. 18).
  • Find "sparse". NVIDIA's 2:4 figures and Cerebras's 125 PF count skipped zeros as work (Ch. 2).
  • Count bytes, not values. A BlockFP8 weight costs 1,088/1,024 B, NVFP4 about 0.56 B, BF16 2 B, and decode speed follows the bytes (Ch. 1).
