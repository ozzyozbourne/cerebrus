Glossary and number formats

The Cerebras, CSL and SDK, Tenstorrent, GPU and general terms the course uses, defined in a sentence or two and linked to the section that explains it. Then the number formats the three machines' peak figures are quoted in, with their bit layouts, two explorers and a table of which machine runs which format.

Use this appendix to

  • Look up a term you met in a chapter, a paper or an SDK example, and jump to the section that teaches it.
  • Read any 4-, 8-, 16- or 32-bit float bit by bit, and see how much precision each format keeps.
  • See why block-scaled formats (BlockFP8, NVFP4, MXFP4) can store 4 to 8 bits per value, and what an outlier does to them.
  • Check which machine supports a format before you compare two peak figures.

Provenance tags work as in the chapters: Vendor Independent SDK 2.10.1 Measured Analyst Derived Unverified. Labels such as “Secondary” or “Vendor via secondary” mark a second-hand report; Appendix E's tag table defines each class (also Provenance tags). Glossary definitions repeat what the linked chapter says, and that chapter's tags apply. The CUDA-to-CSL map, the per-PE budget and the measured cost constants are in Appendix B.

Acceptance rate (α)General#
The probability that the target model accepts a draft token. With k drafts a pass yields (1 − αk+1)/(1 − α) tokens on average: 3.36 at α = 0.8, k = 4. It depends on how predictable the text is, which is why speculative speedups vary from prompt to prompt.See Ch. 9, Speculative decoding on an SRAM machine

Mark a task ready to run by setting its activated bit, with @activate(id) in code or .activate = id on an async op. The bit is a single bit, so two activations that land before the task runs give one run. Back-pressureCerebras#
When a router's buffer for a color is full, the wavelet waits where it is and the stall spreads upstream until the sender stops. The fabric never drops data; a slow receiver slows its sender.See Ch. 4, Nothing is dropped · Ch. 12, When a PE is late
Bank clash (operand collision)Cerebras#
An empirical rule from this course's runs: @fmacs runs at half speed when its two source streams start at word addresses equal mod 4 (byte addresses equal mod 16). Why mod 4: under the SDK's bank rule (bits [3:1] of the byte address), an f32 at word w occupies banks 2w mod 8 and 2w+1 mod 8, so two words share both banks exactly when w₁ ≡ w₂ (mod 4) Derived. Padding one array by a word fixes it. Other ops differ: on WSE-2, f16 @fmach is fast only when the sources start 8 B apart mod 16 B (4 banks) and runs at half speed at 0 or 2 banks apart, while WSE-3 shows no penalty Measured. One rule covers them: peak rate needs the two source streams in opposite halves of the 16-byte bank cycle; the physical bank width is unpublished, so pad and measure. Related: Bank (SRAM bank).See Ch. 6, Layout matters · App. E, Open factual issues · App. B, Measured cost constants · Ch. 14, Measurements and the compute-bound regime
Bank (SRAM bank)Cerebras#
The 48 KB SRAM is 8 single-ported banks. The SDK's rule is that bits [3:1] of the byte address pick the bank (a 16-byte stripe: each bank holds 16 bits of it); papers describe 32-bit interleaving instead, and the physical bank width is not published. Two operands that hit the same bank in one cycle collide: see Bank clash. Related: Bank clash.See Ch. 3, Which bank does an address land in? · Ch. 6, Layout matters: operand collisions in SRAM
bf16 (bfloat16)General#
A 16-bit float with fp32's 8-bit exponent and only 7 mantissa bits: the range of fp32 at a relative step of 7.81 × 10−3. The format of H100's 989 TF and of Tenstorrent tiles.See this appendix, Number formats · this appendix, Which machine runs which format

Draft cost cGeneral#
In speculative decoding, the draft model's cost per token divided by the target's. The speedup is E / (1 + k·c) on a GPU and E / (1 + k/S + k·c) on the wafer pipeline of S stages. On a GPU c is about the ratio of model sizes (0.05–0.1 for 8B vs 70B); on the wafer a draft still pays latency-bound collectives on every layer, so the course estimates c ≈ 0.3–0.4.See Ch. 9, Speculative decoding on an SRAM machine
Draft model / target modelGeneral#
In speculative decoding, the small, fast model that guesses the next tokens (draft) and the large model whose output is wanted (target). Its relative cost per token, the draft cost c, sets how much of the speedup survives. Cerebras has not published which draft model it uses or where it runs it.See Ch. 9, Speculative decoding on an SRAM machine
DSD (data structure descriptor)CSL & SDK#
A value that describes a whole vector operand: base address, length and stride for memory, or a queue and extent for the fabric. One DSD instruction walks it in hardware, with no per-element fetch or branch. In code it is made with @get_dsd, e.g. @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{n} -> u[i] }), and changed with the DSD mutators. Related: @get_dsd · DSD mutators · DSR · Fabric DSD.See Ch. 6, One instruction, a whole loop
DSD mutators (@increment_dsd_offset, @set_dsd_length, @set_dsd_base_addr)CSL & SDK#
Builtins that take a DSD and return a changed copy; none touches memory. @increment_dsd_offset(d, k, T) moves the start by k elements of type T, @set_dsd_length(d, n) sets the extent, @set_dsd_base_addr(d, p) points it at another array, and @set_dsd_stride(d, s) sets the stride. Example (program 07, Lab 5): dsd_b = @set_dsd_length(dsd_b, len); fits DSDs declared at the maximum size to the run-time problem. In a scalar loop they turn 1-D instructions into a 2-D algorithm (A_dsd = @increment_dsd_offset(A_dsd, 1, f32); steps a GEMV one column per @fmacs), but each trip of such a loop costs about 33–35 cycles Measured (simulator, Ch. 6), so keep the inner loop inside the descriptor. Number formats

A floating-point number is a sign bit, an exponent field and a mantissa (fraction) field. With an exponent field of e bits and bias b, a normal number is (−1)s × 1.mantissa × 2exponent−b, and an all-zero exponent gives subnormals near zero. More exponent bits buy range; more mantissa bits buy precision. A 16-bit budget can be split either way: IEEE half (fp16) keeps precision, bfloat16 keeps fp32's range. Block formats go further and share one exponent or scale among a block of values. Peak FLOP figures roughly double with each halving of bits (Chapter 17), so read the format before the number.

What CSL's f16 is: a check in the compiler

We compiled a one-PE program that stores @bitcast(u16, @as(f16, v)) for sixteen constants and read the words back Measured, cslc + simulator 2.10.1, WSE-3. With the default format, 1.0 is 0x3C00, 2.0 is 0x4000, 0.5 is 0x3800, 1.5 is 0x3E00 and 1 + 2−6 is 0x3C10: exactly IEEE half precision. Two more findings:

  • The same constants gave the same bit patterns with --fp16-format=bf16 and =cb16, so in this test the flag did not change how compile-time constants are encoded Measured. The test cannot tell whether the hardware then reads those words differently.
  • With bf16 or cb16 selected, any run-time f16 variable or array (var h: [16]f16;) failed to compile with error: variable of type '[16]f16' must be comptime-known, on both --arch=wse2 and wse3 Measured. So in SDK 2.10.1 a kernel cannot switch its f16 arrays to bfloat16 just with this flag. The SDK documentation for the flag was not available here; how cb16 is meant to be used stays open.

Block formats: sharing a scale

An 8-bit or 4-bit float on its own has too little range for real tensors. Block formats give a small group of values one shared exponent or scale, chosen from the block's largest magnitude, and keep only a few bits per value. Tenstorrent's bfloat8_b shares one 8-bit exponent among 16 values and rounds to nearest-even after aligning each value to it Vendor, tt-metal data_formats. NVFP4 stores each value as E2M1 and each block of 16 with an E4M3 scale, plus one FP32 scale per tensor Vendor. The cost is that one large value in a block squeezes the small ones next to it into fewer bits, because they must share its exponent. Try the outlier switch. With it on, per-tensor FP8 E4M3 keeps the small values best: it shares only a scale, and each value still has its own 4-bit exponent, so its range absorbs a 40× outlier. The block formats share the exponent itself, so the outlier's neighbours lose most or all of their bits. In a real tensor the damage stays inside the outlier's block (16 or 32 values) for the block formats, while a per-tensor scale set by the outlier would squeeze every value in the tensor.

Three rules for reading a peak

  • Find the format. B200's 9 PF is FP4; at BF16 it is about 2.25 PF (Ch. 18).
  • Find "sparse". NVIDIA's 2:4 figures and Cerebras's 125 PF count skipped zeros as work (Ch. 2).
  • Count bytes, not values. A BlockFP8 weight costs 1,088/1,024 B, NVFP4 about 0.56 B, BF16 2 B, and decode speed follows the bytes (Ch. 1).
