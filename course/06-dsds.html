DSDs: loops as hardware

With no caches and no DRAM, the WSE needs a different way to make memory access cheap. The answer is the data structure descriptor (DSD): a hardware address generator that describes a whole walk over memory — or over a stream of wavelets — so that a single instruction can process an entire vector.

After this chapter you can

  • Build memory DSDs with base/extent/stride or tensor_access, and predict exactly which words they touch.
  • Use fabric DSDs so that receiving, computing and sending are one instruction.
  • Run DSD operations asynchronously and chain them through tasks.

One instruction, a whole loop

In C you would write for (i = 0; i < N; i++) y[i] += x[i] * a;. In CSL you describe x and y once and issue one instruction (Lab 1, program 01):

course/programs/01-saxpy/pe_program.csl
const x_dsd = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{N} -> x[i] });
const y_dsd = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{N} -> y[i] });

fn saxpy(a: f32) void {
  @fmacs(y_dsd, y_dsd, x_dsd, a);   // y[i] = y[i] + x[i] * a   for all N
  sys_mod.unblock_cmd_stream();
}

The descriptor lives in one of the PE's 48 data-structure registers (DSRs). The datapath walks it, generating addresses and streaming operands through the SIMD lanes, with no per-element instruction fetch or loop counter. The tensor_access form names an induction variable, a bound and an affine index: |i|{M} -> A[i*N] means "M elements starting at A[0], stride N" — a matrix column.

Fabric DSDs: communication is an operand

A fabin_dsd describes "the next extent wavelets arriving on this input queue"; a fabout_dsd describes "send extent wavelets out of this output queue". Plug them into the same builtins and data moves and computes in one step. Lab 2's row reduction is the clearest example — each middle PE does this:

course/programs/03-row-reduce/pe_program.csl
// receive the running sum from the WEST, add my own v, send the result EAST
@fadds(out_dsd, in_dsd, v_dsd, .{ .async = true, .activate = exit_id });
WSE-3 limit: one fabric input per operation "WSE3 does not allow multiple fabric inputs per DSD operation" SDK 2.10.1. To add two incoming streams you first drain one into a FIFO, then operate on FIFO + fabric. Lab 2's reduction only ever has one fabric input, so it runs unchanged on both chips.

Async operations and completion tasks

Add .async = true and the operation runs on a microthread while the CE moves on. Two optional fields say what to do when it finishes: .activate = task_id (run that local task) or .unblock = task_id (lift a block). This is how "callbacks" are spelled on the WSE. Fabric operations should almost always be async: the SDK warns that a blocking fabric op can stall because the CE must stay free to service the memcpy runtime SDK 2.10.1, pipeline-01.

FIFOs extend the tiny hardware queues

Hardware queues hold only a handful of wavelets — one SDK example "stalls when size exceeds 14". @allocate_fifo(buffer) turns an SRAM array into a FIFO that one async op fills and another drains, using two microthreads SDK 2.10.1.

Lab 3's whole update, in three instructions

The stencil keeps ghost cells at both ends of its array so that three overlapping DSDs see the left neighbour, the cell itself, and the right neighbour of every cell:

course/programs/04-heat-stencil/pe_program.csl
const left  = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{n} -> u[i] });
const mid   = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{n} -> u[i + 1] });
const right = @get_dsd(mem1d_dsd, .{ .tensor_access = |i|{n} -> u[i + 2] });

@fadds(lap_dsd, left, right);         // lap = u[i-1] + u[i+1]
@fmacs(lap_dsd, lap_dsd, mid, -2.0);  // lap += -2 u[i]
@fmacs(mid, mid, lap_dsd, alpha);    // u[i] += alpha * lap

Write a DSD for the main diagonal of an 8 × 8 row-major matrix.

|i|{8} -> A[i * 9] (stride 9), or in 2-D form |i|{8} -> A[i, i].

Why is @fadds(out_dsd, in_dsd, v_dsd) faster than receiving into memory and then adding?

It avoids writing the incoming vector to SRAM and reading it back, and overlaps receive, add and send in one pipelined operation.

What does a stride of 0 do?

It visits the same word every time: a broadcast of one memory value as a vector operand.
